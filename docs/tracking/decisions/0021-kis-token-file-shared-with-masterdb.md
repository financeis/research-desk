# 0021 — KIS 접근 토큰은 masterdb와 토큰 파일을 같이 쓰고, 한 실행에 한 번만 받는다

## 배경
한국투자증권(KIS) Open API는 접근 토큰을 앱키당 1분에 한 번쯤만 발급하고, 토큰을 자주 받는 앱키는 이용을 제한한다. 토큰은 하루 동안 유효하다. 이 앱의 `KIS_APP_KEY`는 사용자의 다른 프로젝트(masterdb, 매일 KIS 수집)와 같은 키라서, 두 쪽이 각자 토큰을 받으면 하루에 여러 번 발급하게 된다. 2026-10-10에 확인 실행(`--codes`) 직후 전체 실행을 돌리자 `EGW00133 접근토큰 발급 잠시 후 다시 시도하세요(1분당 1회)`로 멈춘 일이 있었다.

## 결정
- `KIS_TOKEN_CACHE`가 masterdb의 토큰 파일(그 저장소의 `data/state/kis_token.json`, masterdb 형식 `{"access_token", "app_key_tail"(앱키 끝 6자), "expires_at"(초)}`)을 가리키면, 끝나기까지 10분 넘게 남고 앱키 끝 6자가 같은 토큰은 KIS에 묻지 않고 그대로 쓴다. 새로 받은 토큰은 같은 파일에 임시 파일을 거쳐 통째로 바꿔 넣는다(읽는 쪽이 반쪽 파일을 보지 않게).
- KIS가 파일의 토큰을 거절하면(`EGW00121`·`EGW00123`) 한 번만 새로 받아 그 호출을 다시 하고, 그 뒤로는 파일을 다시 읽지 않는다. 클라이언트가 스스로 받은 토큰이 거절되면 다시 받지 않는다.
- 설정이 없으면 예전처럼 실행마다 한 번 받아 메모리에만 둔다. 어느 쪽이든 한 실행은 클라이언트 하나를 쓰고, 토큰 요청이 한 번 실패하면 그 실행 동안 KIS에 다시 묻지 않는다.
- 파일을 못 읽거나 못 써도 경고 한 줄이고 실행은 계속된다. 토큰은 DB·로그·명령 출력에 남기지 않는다.

## 버린 대안
- **실행마다 새로 받기(처음 구현)**: 하루 한 번 실행이면 문제없지만, 확인 실행과 전체 실행을 잇달아 돌리거나 masterdb 수집과 겹치면 1분 발급 제한에 걸리고, 되풀이되면 앱키 이용이 제한된다.
- **이 저장소만의 토큰 파일**: masterdb가 받은 토큰과 따로 받게 되어 하루 발급 횟수가 줄지 않는다. 같은 앱키의 토큰은 하나면 된다.
- **masterdb에 토큰을 나눠 주는 장치 두기**: 두 프로젝트를 코드로 묶는 과잉이다. 파일 하나를 같이 읽고 쓰는 것으로 충분하다.

## 결과
- 이 앱은 masterdb의 파일 형식에 기댄다. 형식이 바뀌면 읽지 못하고 새로 받는다(깨지지는 않는다).
- 토큰이 든 파일은 이 저장소 밖에 있고 경로는 `.env`에만 둔다. 공개 문서에는 masterdb 저장소 안의 상대 위치만 적는다.
- 두 프로젝트의 KIS 실행 시각을 겹치지 않게 두는 일은 사용자가 한다(작업 스케줄러 평일 18:30).
- 이 앱이 토큰 수명을 혼자 관리하지 않게 되었다. masterdb가 받은 토큰이 유효하면 그대로 쓴다.
