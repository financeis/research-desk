# 0028 — 분석 결과가 바뀌거나 지워지면 그 리포트를 앞 문서로 삼은 해석문을 비운다

## 배경
비교 해석문은 두 리포트의 저장된 분석 결과로 만들고, 뒷 문서의 분석 결과 행에 저장한다(`prev_report_id` = 앞 문서). 지금까지 규칙은 이랬다: 뒷 문서를 다시 분석하면 그 해석문이 비워지지만, 앞 문서를 다시 분석하면 다른 행은 건드리지 않아 해석문이 남는다.

이번에 분석 결과를 지우고 다시 분석할 수 있게 되면서 이 규칙의 빈틈이 드러났다. 빈 결과(글자 없는 PDF)로 만든 해석문은 앞 문서의 분석을 고쳐도 그대로 남는다. 앞 문서를 지우면 비교 화면에 "앞 문서 분석은 없는데 해석문만 있는" 상태가 생긴다. 실제로 빈 결과 3건 중 1건이 다른 리포트 3건의 앞 문서로 쓰이고 있었다.

## 결정
- 리포트 X의 분석 결과가 **새로 저장될 때**(처음 분석, 옛 결과 덮어쓰기, 여러 건 분석, 다시 분석 모두)와 **지워질 때**, `prev_report_id = X`인 다른 모든 행의 비교 칸 네 개를 비운다(사용자 선택: 지우기·다시 분석, 그리고 옛 결과 덮어쓰기에도 같은 규칙).
- 비우기는 X의 저장·삭제 **직전에** 한다. 저장·삭제가 실패해도 비운 것은 되돌리지 않는다.
- 화면에서 한 번 더 묻는 것은 `다시 분석`과 `분석 결과 지우기` 버튼뿐이다. 기존 분석 버튼과 여러 건 분석은 묻지 않는다(사용자 선택).
- 해석문을 만드는 동안에는 두 리포트를 "바쁨"으로 표시한다. 그 리포트의 분석·지우기는 409로 막는다. 해석문은 표시를 건 뒤 읽은 분석 결과로 만든다.

## 버린 대안
- **지금 규칙대로 남겨 두기**: 틀렸거나 바뀐 분석을 바탕으로 쓴 해석문이 아무 표시 없이 남는다. 필요하면 비교 화면에서 다시 만들면 된다(사용자가 이 이유로 비우기를 골랐다).
- **비우기를 저장 뒤에 하기**: 두 일은 서로 다른 REST 호출이라 한 트랜잭션이 아니다. 저장은 됐는데 비우기가 실패하면, 바뀐 결과를 기준으로 한 옛 해석문이 아무 표시 없이 남는다. 비우기를 앞에 두면 최악의 경우가 "해석문만 사라짐"이고, 해석문은 다시 만들 수 있다.
- **DB 함수 하나로 저장과 비우기를 한 트랜잭션에**: 저장 payload를 DB 함수로 옮겨야 해서 바뀌는 범위가 크다.
- **여러 건 분석에도 확인 창**: 사용자가 묻는 것은 다시 분석·지우기 버튼으로 충분하다고 했다.
- **"바뀌었나"를 `generated_at`으로 판단**: 이 칸은 처음 넣을 때만 채워져, 다시 분석해도 바뀌지 않는다.

## 결과
- 앞 문서를 고치거나 지우면 그 문서를 기준으로 한 해석문이 사라진다. 비교 화면에서 다시 만들어야 한다.
- 옛 결과(재무 상세 없음)를 처음 상세 분석할 때도 그 리포트를 앞 문서로 삼은 해석문이 사라진다.
- 해석문을 만드는 동안(AI 자리를 기다리는 동안 포함) 두 리포트의 분석·지우기가 409다. 같은 리포트가 낀 다른 짝의 해석문을 동시에 만들어도 뒤의 것이 409다.
