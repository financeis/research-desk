# 0019 — 발행처는 사전의 닫힌 목록 안에서 AI가 고르고, 파일 이름 표기는 의심 표시·다시 분류 대상 고르기에만 쓴다

## 배경
발행처 오류의 원인이 세 겹이었다.
- AI가 발행처 칸에 아무 글이나 쓸 수 있었다. "확인 불가" 같은 문장이나 `Eugene` 같은 별칭이 그대로 저장됐다.
- 사전에 빠진 발행처(신영증권, 한양증권, 리딩투자증권 등)가 있어 AI가 비슷한 다른 이름을 붙였다.
- 옛 모델이 다른 증권사로 잘못 붙인 행(다올→대신 등)이 남아 있었다.

발행처는 비교 화면의 "같은 증권사의 의견 변경 / 다른 증권사의 견해 차이" 판정, 커버리지의 발행처 비중, 분석 메타데이터에 쓰인다.

그 전 규칙은 분류기 안내에 적힌 "코드 대조를 되살리지 않는다"였다. 영문·별칭·부서명이 섞인 발행처를 코드로 맞추다 실패한 경험에서 나온 규칙이라, 정규화는 통째로 AI에 맡기고 코드는 AI가 낸 이름과 종류를 그대로 저장했다.

## 결정
- 발행처 사전 `research_desk/tagger/vocabulary/publishers.yaml`이 발행처 이름의 유일한 원본이다. 항목은 정식 이름과 별칭이고, 항목이 들어 있는 구역이 발행처 종류다.
- AI는 사전의 정식 이름 하나 또는 null만 답한다. 응답 모양의 발행처 칸이 정식 이름 목록이고, 코드는 답이 정식 이름과 글자 그대로 같은지만 확인해 아니면 null로 저장한다. 이 확인은 오류를 내지 않는다 — 오류로 처리하면 같은 행이 배치마다 대기 줄로 되돌려지는 고리가 생긴다.
- 발행처 종류는 AI에게 묻지 않고, 저장한 이름의 사전 구역에서 가져온다.
- 예전 규칙을 다음 셋으로 좁힌다.
  - PDF 속 글자를 코드로 대조해 발행처를 정하지 않는다(판단은 AI).
  - 코드는 AI 답이 사전의 정식 이름인지 확인만 한다.
  - 파일 이름 표기(`_YYYYMMDD_<표기>_<숫자>.pdf`의 `<표기>`)는 저장할 값을 정하지 않는다. 의심 표시(`publisher_suspect:filename_mismatch`, `publisher_suspect:unknown`)와 다시 분류 대상 고르기(`tag requeue --publisher-filename-mismatch`)에만 쓴다.
- 의심 행은 검토 대기로 보내지 않는다. 상태는 그대로 두고 신뢰도만 최대 `medium`으로 낮추고 메모를 남긴다.
- 사전 정비 기준.
  - 정식 이름은 표지에 적힌 지금 회사명이다. 한국어 정식 상호가 있으면 그것을 쓴다(예: `DB증권`, `한국IR협의회`, `iM증권`, `에프앤가이드`, `한국거래소`, `지엘리서치`, `다인자산운용`, `IR큐더스`).
  - 증권사가 아닌 독립 리서치는 `data_provider`다.
  - `미래대우증권`은 뺐다. 수집 리포트는 2025년 이후라 맞는 리포트가 없다.
  - 신용평가사 항목은 뺐다. 기술분석보고서는 표지의 작성기관(한국기업평가·NICE신용평가·NICE평가정보·한국기술신용평가·서울평가정보)과 상관없이 `한국IR협의회`로 둔다(사용자 결정, 2026-10-10). 채널에서 신용평가사가 실제 발행처로 나온 일은 없었고, 저장된 쓰임은 모두 한국IR협의회가 맡긴 기술분석보고서였다. 작성기관 이름은 `한국IR협의회`의 별칭이다.
  - 채널의 파일 이름 표기는 모두 별칭으로 넣는다. 정식 이름은 서로 겹치지 않고, 별칭·표기 하나는 정식 이름 하나에만 대응하며 다른 항목의 정식 이름과도 같지 않다. 이 기준은 테스트(`research_desk/tagger/tests/test_vocabulary.py`)가 지킨다.

## 버린 대안
- **파일 이름 표기로 발행처를 확정**(표기가 사전 별칭과 맞으면 그 정식 이름을 AI 답보다 먼저 저장): 사용자가 뺐다. 판단은 AI에 두고 표기는 신호로만 쓴다. 나중에 "표기가 대부분 맞으니 그걸로 저장하자"로 바꾸지 않게 이 이유를 남긴다.
- **코드가 PDF 글자에서 발행처 이름을 찾아 맞추기**: 예전에 실패한 방식이다.
- **정식 이름이 아닌 답을 검증 오류로 처리**: 같은 행이 배치마다 `pending`으로 되돌려지는 고리가 생긴다.
- **의심 행을 검토 대기로 보내기**: 검토 대기는 승인 전까지 기업 화면에 안 나온다. 사용자의 방향은 "일단 화면에 띄우고 애매한 것은 나중에 내가 분류"다. 지금 검토 화면에는 발행처를 직접 고르는 기능도 없다.
- **발행처 원문 이름 칸을 따로 두기**: 새 증권사는 거의 없을 것이고 "모름"은 모름인 채로 둔다. 사전 보충 신호는 `tag requeue` 미리 보기의 `unknown_filename_tags`로 충분하다.

## 결과
- 지금 규칙으로 분류된 행의 발행처는 사전의 정식 이름이거나 비어 있고, 종류는 그 이름의 사전 구역이거나 비어 있다.
- 사전을 고치면 AI 요청(시스템 프롬프트, 응답 모양의 정식 이름 목록)이 바뀐다. 백필 중에는 고치지 않고, 고친 뒤 `tag requeue`로 다시 분류한다(0020).
- 사람이 승인한(`verified`) 행은 다시 분류하지 않으므로 사전에서 바뀌거나 빠진 옛 이름을 그대로 가진다(아직 못 푼 문제로 남아 있다).
- 기술분석보고서끼리는 작성기관이 달라도 비교에서 같은 발행처다.
- 사람이 발행처를 직접 고르는 화면은 다음 작업이다.
