# 0020 — 다시 분류는 대기 줄로 되돌리는 `tag requeue`로 한다

## 배경
발행처 사전을 고치거나 분류 규칙이 바뀌면, 이미 분류된 행을 지금 규칙으로 다시 분류해야 한다. 그림 경로가 생기기 전에 못 읽음으로 간 행, 사전에서 이름이 바뀌거나 빠진 발행처, 파일 이름 표기와 다른 발행처, 종목표를 바꾼 뒤에도 남은 미매칭 행이 그렇다. 그 전에는 길이 검토 화면의 재분류(한 건씩, `review_needed`만)와 `tag run --row-ids`(상태 확인도 가져가기 표시도 없는 알려진 문제가 있음)뿐이었다.

## 결정
- `python -m research_desk tag requeue`가 고른 조건(`--unreadable`, `--publisher-not-in-dictionary`, `--publisher-filename-mismatch`, `--publisher-type-mismatch`, `--krx-unmatched` 중 하나 이상)에 맞는 `auto`·`review_needed` 행을 분류 전(`pending`)으로 되돌린다. 다시 분류는 평소 백필(동시 2·배치 10, 되돌리기·재시도 장치 그대로)이 지금 규칙으로 한다. 이 명령은 AI를 부르지 않는다.
- 기본은 미리 보기다(아무것도 쓰지 않는다). `--apply`는 이 순서다: 이 PC에서 백필·재처리·수집·웹앱이 돌고 있으면 아무것도 바꾸지 않고 1, 프로세스 목록을 못 읽으면 4 → 대상을 다시 고름 → 바뀔 행의 값을 백업 CSV(`backups/requeue/`, git 무시)에 먼저 씀 → 한 트랜잭션에서 행을 잠그고, 백업과 같고 여전히 조건에 맞는 행만 되돌리고, 되돌린 수가 다시 확인한 수와 다르면 모두 취소.
- 되돌리는 모양은 검토 화면의 재분류와 같고, 정의는 `research_desk/domain/reports.py`의 `pending_reset_shape` 한 곳이다. 분류기와 검토 기능은 서로 import하지 않으므로 둘이 같이 쓰는 자리가 domain이다.
- 사람이 승인한 `verified` 행은 어떤 조건에서도 고르지 않는다.
- 백업은 기록용이다. 백업에서 되돌리는 명령은 만들지 않는다(사용자 결정).
- 종료 코드는 0004·0015의 규칙을 따른다. 사전을 못 읽음, `--unreadable`인데 분류 모델이 그림을 받지 못함, 프로세스 목록을 못 읽음은 고쳐야 풀리는 준비 문제라 4다. 돌고 있는 작업(백필·재처리·수집·웹앱) 때문에 거절한 경우는 그 작업이 끝나거나 꺼지면 풀리는 상태라 1이다(0015의 "분류 작업 진행 중"과 같다). 어느 쪽이든 아무것도 바꾸지 않고, 무엇을 할지 stderr 한 줄로 알린다(사용자 결정, 2026-10-10).
- 같은 행이 실행마다 되돌려지는 고리를 막는다. `--unreadable`은 지금 1쪽 그림을 만들 수 없는 행을 고르지 않고, 분류 모델이 그림을 받지 못하면 4로 멈춘다. `--publisher-filename-mismatch`는 의심 표시가 이미 붙은 행(지금 규칙으로 확인됨)과 못 읽음·거부 행(AI 결과가 없어 의심 표시가 붙지 않음)을 고르지 않는다.

## 버린 대안
- **`tag run --row-ids`로 다시 분류**: 가져가기 표시가 없어 백필과 겹칠 수 있고 상태를 확인하지 않는다(알려진 문제).
- **고른 행을 바로 다시 분류해 덮어쓰는 새 경로**: 검토의 재분류와 다른 쓰기 경로가 하나 더 생기고, 백필의 동시 처리·되돌리기·재시도 장치를 다시 만들어야 한다.
- **백업에서 되돌리는 명령**: 사용자가 만들지 않기로 했다.
- **저장된 비교의 자동 갱신**: 사용자가 뺐다. 발행처가 바뀐 리포트의 저장된 비교는 필요하면 운영 절차로 비운다. 분석 결과 표는 분석 기능의 것이라 분류기가 읽지도 고치지도 않는다.

## 결과
- 사전을 고친 뒤의 절차가 정해졌다: 백필·수집·웹앱 끄기 → 미리 보기 → `--apply` → 백필 → (필요하면) 저장된 비교 비우기(비교 칸 네 개만, 백업 → 한 트랜잭션 → 건수 확인).
- 실행 확인은 Windows 프로세스 목록의 명령줄로 한다. 관리자 권한으로 띄운 프로세스는 명령줄이 보이지 않아 찾지 못한다(아직 못 푼 문제로 남아 있다).
- 되돌린 행은 다시 분류될 때까지 웹 목록에서 빠지고, 새로 수집한 리포트보다 먼저 다시 분류된다.
- 여러 문장을 한 트랜잭션에서 돌릴 수 있게 `core.db`에 `SupabaseSQL.transaction()`이 생겼다.
- 종목표를 바꾼 뒤에는 `--krx-unmatched`로 쌓인 미매칭 행을 다시 분류할 수 있다.
