# 0012 — 주가는 `prices` 기능이 주인이고, KIS에서 매일 받아 최신 스냅샷만 둔다

> 일부를 [0026](0026-prices-keep-a-year-of-adjusted-closes.md)이 바꿈(2026-10-11): "일별 이력 표는 두지 않는다" 대신 1년치 수정 종가 이력(`stock_price_daily`)을 둔다. 나머지는 그대로다.

## 배경
유사 기업 화면은 "아직 덜 오른" 회사를 가리려고 종목마다 기간 수익률, 시장 대비 초과수익률, 20일 평균 거래대금, 거래정지 여부가 필요했다. 앱에는 주가가 없었다. 앞으로 퀀트 연결 같은 다른 기능도 주가를 쓸 예정이라, 여러 기능이 같이 쓸 데이터를 누가 갖고 어떻게 받을지 정해야 했다. 텔레그램 수집이 몇 주 멈춘 것을 아무도 몰랐던 일이 있어, 매일 도는 작업이 멈추면 바로 보여야 했다.

## 결정
- `features/prices`가 주가 표 두 개(`stock_price_snapshot`, `price_update_runs`)의 주인이다. 다른 기능은 `prices.snapshots(codes)`·`prices.latest_run()` 창구로만 읽는다.
- 출처는 한국투자증권(KIS) Open API 실전 계정이다. 평일 장 마감 뒤 윈도우 작업 스케줄러가 `scripts/run-prices.ps1` → `python -m research_desk prices update`를 부른다(사용자 선택: 매일 자동).
- 종목당 최신 스냅샷 한 행만 둔다. 실행마다 KIS의 수정주가 시계열을 받아 수익률을 처음부터 다시 계산한다. 일별 이력 표는 두지 않는다.
- 초과수익률은 같은 실행·같은 시장(코스피/코스닥) 수익률 중앙값 대비다. 받지 못한 종목이 20%를 넘으면 그 실행은 실패이고 스냅샷을 하나도 바꾸지 않는다.

## 버린 대안
- **일별 이력 표**: KIS가 수정주가 시계열을 한 번에 주므로, 매번 다시 계산하면 무상증자·액면분할 보정을 따로 할 필요가 없다. 이력을 쌓으면 그 보정을 직접 맞춰야 한다. 일별 이력은 앞으로 붙일 퀀트 기능이 필요할 때 정하고, 연구용 이력은 사용자의 다른 프로젝트(masterdb)에 있다.
- **기능마다 따로 주가 받기**: 같은 앱키로 호출 한도와 접근 토큰 발급을 나눠 쓰게 되고, 같은 값이 기능마다 다르게 계산된다.

## 결과
- 지금은 1주·1개월·3개월·6개월 수익률(5·21·63·126거래일)만 있다. 다른 기간, 과거 날짜 기준 수익률, 주가 차트, 백테스트는 이력 표를 `prices`에 더하기 전에는 할 수 없다.
- 실행이 실패하면 이전 스냅샷이 그대로 남고, 상태 줄의 주가 기준일이 밀림을 알린다. 일부 실패(20% 이하)면 받지 못한 종목은 이전 값에 `no_data` 표시가 붙는다.
- KIS 키는 사용자의 다른 프로젝트(masterdb)와 같은 키라서, 두 쪽의 KIS 수집을 같은 시간에 돌리지 않는다.
- 초과수익률은 지수가 아니라 그 실행에서 받은 종목들의 시장별 중앙값 대비다. 받은 종목이 적은 확인 실행(`--codes`)은 저장된 스냅샷 전체의 중앙값을 쓴다.
