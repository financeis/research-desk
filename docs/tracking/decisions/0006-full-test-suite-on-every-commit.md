# 0006 — 커밋과 병합 커밋마다 전체 테스트를 돌린다

## 배경
예전에는 누가 테스트를 돌려야만 검사가 됐다. AI가 빼먹으면 규칙을 어긴 코드가 그대로 저장됐다. 실제로 `pytest`가 테스트 397개 중 69개만 모으고 있던 일이 있었다. 칸 사이 import 경계와 표 주인을 지키는 구조 검사도 테스트로 돌기 때문에, 테스트가 돌아야 경계가 지켜진다.

## 결정
- `.githooks/pre-commit`·`.githooks/pre-merge-commit`이 같은 검사 스크립트(`.githooks/run-checks.sh`)를 부르고, 이 스크립트가 구조 검사를 포함한 전체 테스트(`python -m pytest -q -p no:cacheprovider`)를 돌린다. 실패하면 커밋을 막는다(사용자 선택).
- 파이썬은 기본 작업 폴더(`git rev-parse --git-common-dir`의 상위 폴더)의 `.venv`를 쓴다. 별도 작업 폴더(git worktree)에서 커밋해도 같은 파이썬을 찾는다. 없으면 이유를 찍고 막는다.
- `git config core.hooksPath .githooks`로 켠다. `--no-verify`로 건너뛰는 것은 금지다.

## 버린 대안
- **바뀐 파일과 관련된 테스트만**: 구조 검사는 트리 전체를 봐야 의미가 있고, 전체 테스트가 30초 남짓이라 고를 이유가 없다.
- **원격 CI**: 로컬 단일 사용자 저장소이고 GitHub에 자주 올리지 않는다. 커밋 순간에 막아야 한다.

## 결과
- 커밋 하나에 30초 남짓 걸린다. 테스트가 느려지면 커밋이 느려지므로, 느린 테스트(하위 프로세스 실행 등)는 꼭 필요한 것만 둔다.
- 테스트는 바깥 상태(실제 `.env`, `frontend/dist`, 관심 기업 파일)에 기대면 안 된다. 커밋 검사는 실제 `.env`가 있는 기본 작업 폴더에서도 돌기 때문이다.
- 새로 복제한 저장소는 `core.hooksPath`를 켜기 전까지 검사가 없다(설치 순서의 한 단계가 `git config core.hooksPath .githooks`다).
