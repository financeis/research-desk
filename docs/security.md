# 보안

## 지키는 것

| 자산 | 왜 중요한가 |
|---|---|
| `SUPABASE_SERVICE_KEY` | 행 수준 보안(RLS)을 우회한다. 모든 표를 읽고 쓰고 지울 수 있는 마스터 비밀번호다. 표마다 RLS가 켜져 있어 익명·일반 사용자 키로는 접근이 거부되므로, 이 키가 곧 DB 전체 권한이다 |
| `SUPABASE_DB_URL` | Postgres 비밀번호가 들어 있는 직접 연결 주소. 서비스 키와 같은 무게다 |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` | 과금되는 API 키 |
| `TELEGRAM_API_ID`/`TELEGRAM_API_HASH`와 `sessions/<이름>.session` | 세션 파일은 텔레그램 계정에 로그인된 상태 그 자체다. 파일을 가진 사람은 문자 인증 없이 그 계정으로 접속한다 |
| Codex CLI 로그인(사용자 홈의 codex 설정) | ChatGPT 계정 한도를 쓴다 |
| 로컬 PDF 폴더(`STORAGE_BASE_DIR`) | 수집한 리포트 원본 |
| 다시 분류 백업 `backups/requeue/*.csv` | `tag requeue --apply`가 되돌리기 전에 남긴 행 값(파일 이름, 분류 결과). 저장소 안이지만 git이 무시한다(`/backups/`) |
| 관심 기업 파일 `~/.review_viewer/favorites.json` | 사용자 데이터. 웹앱만 읽고 쓴다 |
| `KIS_APP_KEY`, `KIS_APP_SECRET` | 한국투자증권 실전 계좌에 묶인 Open API 앱키·시크릿. 이 앱은 시세·투자자별 매매 조회(`prices update`, `flows update`)에만 쓰지만 같은 키로 그 계좌의 다른 API(주문 등)도 부를 수 있어 서비스 키와 같은 무게로 다룬다. 사용자의 다른 프로젝트(masterdb)와 같은 키다 |
| KIS 접근 토큰 | 하루짜리. `KIS_TOKEN_CACHE`가 있으면 masterdb와 같이 쓰는 토큰 파일(이 저장소 밖, masterdb가 git에서 빼 둔 `data/state/kis_token.json`)에서 유효한 토큰을 먼저 쓰고, 새로 받은 토큰은 그 파일에 쓴다 — KIS는 토큰을 자주 받는 앱키를 제한한다. 없으면 실행마다 한 번 받아 메모리에만 둔다. 어느 쪽이든 DB·로그·명령 출력에는 남기지 않는다 |
| `kis_devlp.yaml`(저장소 루트, git 무시) | KIS 샘플 코드용 설정 파일. 실전 앱키·시크릿·계좌번호가 그대로 들어 있다. 이 앱은 읽지 않고(`.env`만 읽는다) 열지도 커밋하지도 않는다 |
| `DART_MONGO_URL`과 사업보고서 MongoDB(`FS.A001_v2`) | 주소에 비밀번호가 들어갈 수 있다. 데이터는 별도 DART 수집 프로그램의 것이고 이 앱은 읽기만 한다 |

## 접근 경로와 인증

로그인이 없다. 혼자 쓰는 로컬 앱이라 **이 PC에서 `127.0.0.1:8520`에 닿을 수 있는 것 = 모든 권한**이다. 그래서 경계는 네트워크와 요청 출처에 둔다.

1. 서버는 `127.0.0.1`에만 묶여 연다. 다른 기기에서는 접속할 수 없다.
2. 요청의 `Host`가 `127.0.0.1`, `localhost`, `testserver`가 아니면 400으로 거절한다. DNS 리바인딩(악성 페이지가 자기 도메인을 127.0.0.1로 돌려 접속)을 막는다.
3. GET·HEAD·OPTIONS가 아닌 요청에 `Origin` 헤더가 있고, 그 호스트가 `127.0.0.1:8520`, `localhost:8520`, `127.0.0.1:5173`, `localhost:5173`(개발용 화면 서버)이 아니면 403 `{"detail": "허용되지 않은 요청입니다."}`로 거절한다. 브라우저에서 다른 사이트가 이 서버로 쓰기 요청(검토 처리, 관심 기업, 분석 실행·다시 분석, 분석 결과 지우기)을 보내는 것을 막는다.
4. `Origin`이 없는 쓰기 요청(같은 PC의 스크립트·curl)은 허용한다. 이 PC 안의 프로그램은 믿는다는 뜻이다.
5. AI를 부르는 주소는 GET으로 두지 않는다. 출처 검사는 GET이 아닌 요청에만 걸리므로, AI를 부르는 GET 주소가 있으면 다른 사이트가 이미지 태그 하나로 이 PC의 AI 비용을 일으킬 수 있다. 그래서 테마 검색(질의 임베딩)도 `POST /api/peers/search`이고, 유사 기업 탭(`GET`)은 AI를 부르지 않는다.

| 누가 | 무엇을 | 조건 |
|---|---|---|
| 이 PC의 브라우저(이 서버나 5173 개발 서버가 연 화면) | 모든 읽기·쓰기 주소 | 허용 호스트 |
| 이 PC의 다른 프로그램(Origin 없음) | 모든 주소 | 허용 호스트 |
| 다른 사이트를 연 브라우저 탭 | GET은 보낼 수 있지만 응답을 읽지 못한다(CORS 허용 헤더가 없다). 쓰기는 403. 단 GET에도 부작용이 하나 있다: `GET /api/workspace`는 깨진 관심 기업 파일을 `.json.bak`으로 옮긴다 | — |
| 다른 기기 | 접속 불가 | 127.0.0.1에만 묶임 |
| 누구든 | `/docs`, `/redoc` 화면 | 꺼져 있다(404). `/openapi.json`은 켜져 있다(이 PC 안에서만 열리므로) |

다른 기기에서 접속해야 하게 되면, 로그인 같은 접근 제어를 웹 서버 조립부(`research_desk/web/app.py`) 한 곳에 붙인다. 기능마다 따로 붙이지 않는다. 그 전에 127.0.0.1 묶음이나 허용 호스트를 풀면 위 표의 "누구든 모든 권한"이 네트워크 전체로 퍼진다.

## 브라우저에 절대 보내지 않는 것

- 키·서비스 키·DB 주소. 서버의 `.env`에만 있다. 화면 쪽 코드는 키 없이 `/api`만 부른다.
- 로컬 파일 경로. 리포트 공개 모양은 `file_path`를 빼고 `pdf_url`(`/api/reports/{id}/pdf`)만 준다. 검토 대기열 응답도 `file_path`를 빼고 `pdf_url`(`/api/review/{id}/pdf`)을 붙인다.
- 오류 추적 내용. 예기치 못한 오류는 로컬 로그에만 남기고 응답은 고정 문장 503이다. 기능 사용 불가(503) 응답의 이유 문구에는 키 이름은 들어갈 수 있지만 파일 경로·키 값·오류 추적은 넣지 않는다.
- 명령(`python -m research_desk …`)의 출력은 이 PC의 터미널에만 보이므로 파일 경로를 넣어도 된다.

## PDF 내주기

- PDF는 리포트 번호로만 내준다. 요청에서 경로를 받지 않는다.
- DB의 `file_path`를 저장 폴더(`STORAGE_BASE_DIR`) 기준으로 풀어서, 결과가 저장 폴더 **안**에 있고 확장자가 `.pdf`일 때만 내준다. `../`로 밖을 가리키거나, 저장 폴더 밖 절대 경로이거나, `.env`처럼 PDF가 아니면 404 `PDF를 찾을 수 없습니다.`, 파일이 없으면 404 `로컬 PDF 파일이 없습니다. 수집 상태를 확인해 주세요.`다.
- 리포트 PDF는 분석 대상 행만, 검토 PDF는 그 번호의 행이 있을 때만 내준다.

## 외부로 나가는 데이터

- 분류: 리포트 첫 1~3쪽 글자와 파일 이름·캡션·보낸 시각이 분류 모델 공급자(Anthropic/OpenAI)로 간다. 1~3쪽에 글자가 하나도 없는 PDF는 글자 대신 **1쪽 그림(PNG, 120dpi — 공급자 한도보다 크면 더 낮은 해상도)**이 같은 공급자로 간다(Anthropic API, OpenAI API, `codex:` 모델이면 로컬 Codex CLI가 임시 폴더의 그림 파일을 붙여 OpenAI로 보낸다). 그림에는 그 쪽에 보이는 모든 것(표지, 애널리스트 이름과 연락처 등)이 담긴다.
- 분석·비교: 사용자가 고른 리포트의 PDF 전체 글자(한도까지)와 저장된 분석 결과가 분석 모델 공급자로 간다. 본문 글자가 사실상 없는 PDF(그림 분석)는 글자 대신 **앞 최대 20쪽의 그림(PNG, 120dpi — 공급자 한도보다 크면 더 낮은 해상도)**이 같은 공급자로 간다(`codex:` 모델이면 로컬 Codex CLI가 임시 폴더의 그림 파일을 붙여 보낸다). 그림에는 그 쪽에 보이는 모든 것(표지, 애널리스트 이름과 연락처, 배포처 표시 등)이 담긴다. 그림은 브라우저로 보내지 않는다. `codex:` 모델이면 로컬 Codex CLI가 사용자 설정을 무시하고, 빈 임시 폴더를 작업 폴더로 삼아, 읽기 전용 샌드박스로 실행된다(파일을 쓰지 못하고, 작업 폴더에 저장소가 없다). 입력은 프롬프트로만 넘기고 출력은 정해진 JSON 스키마로만 받는다.
- 유사도 계산(`peers build`): 회사마다 사업보고서에서 조립한 입력 글(최대 12,000자)과 회사명이 프로필 모델 공급자(Anthropic/OpenAI/Codex)로 간다. 프로필 요약 글(틈새 업종·요약·제품·키워드·사업부문·적용처 — 고객사·경쟁사는 빼고)이 OpenAI 임베딩으로 간다.
- 테마 검색: 사용자가 입력한 검색어(공백 정리·동의어 정규화 뒤)가 OpenAI 임베딩으로 간다. 같은 검색어는 서버 캐시로 답해 다시 보내지 않는다.
- 주가 갱신(`prices update`)·수급 갱신(`flows update`): 종목코드와 날짜(주가는 날짜 범위, 수급은 끝 날짜와 시장 `J`)가 KIS로 간다. 앱키·시크릿은 요청 머리글과 토큰 요청 본문에만, 토큰은 요청 머리글에만 실린다. 웹앱은 KIS를 부르지 않는다.
- `LANGSMITH_TRACING=true`이면 위 프롬프트와 응답(사업보고서 입력 글 포함)이 LangSmith에도 기록된다. 분류의 1쪽 그림도 요청과 그래프 실행 기록에 함께 실려 간다. 켜지 않으면 보내지 않는다.
- `tag requeue`는 AI를 부르지 않고 외부로 아무것도 보내지 않는다(DB와 로컬 PDF, 로컬 프로세스 목록만 읽는다).

## 비밀 값 관리

- 모든 비밀 값은 저장소 루트의 `.env` 한 곳에 둔다. `.env`, `.env.*`(단 `.env.example` 제외), `*.session`, `sessions/`, `/kis_devlp.yaml`은 git 무시 대상이다. `.env.example`에는 실제 값을 넣지 않는다.
- 비밀 값을 로그·명령 출력·커밋 메시지·테스트 고정값에 넣지 않는다. 테스트는 가짜 값(`sk-ant-test` 같은)을 쓴다.
- 만료·교체는 자동이 아니다. 새는 것이 의심되면: 공급자 콘솔(Supabase / Anthropic / OpenAI / my.telegram.org)에서 키를 다시 발급하거나 세션을 끊고 → `.env`를 고치고 → 돌고 있는 분류 작업과 웹앱을 다시 켠다. `.env`에 이미 있던 값을 바꾼 것은 다시 켜야 반영된다.
- KIS 키를 다시 발급하면 같은 키를 쓰는 masterdb 프로젝트의 `.env`도 사용자가 함께 고쳐야 한다. `prices update`·`flows update`는 실행마다 새 프로세스라 다음 실행부터 새 키를 쓴다.
- KIS 오류 문장과 로그에는 앱키·시크릿·토큰을 넣지 않는다. KIS 응답이 그 값을 되풀이하면 `core.kis`가 `***`로 가린다. 실행 기록의 메시지와 명령 출력도 이 가린 문장만 쓴다. MongoDB 주소는 로그에 오류 종류만 남긴다.
- 사용자의 다른 프로젝트(masterdb)의 `.env`와 이 저장소 루트의 `kis_devlp.yaml`은 열지 않는다(실제 계좌 키가 있다). KIS 호출 방법을 참고할 때도 그 프로젝트의 코드만 읽는다.
- Codex 로그인이 만료되면 `codex login`으로 다시 로그인한다. 텔레그램 세션 파일이 사라지면 다음 `collect`에서 문자 인증을 다시 한다.

## 기록

- 누가 무엇을 했는지 남기는 감사 기록은 없다(사용자가 한 명). 남는 것: 리포트 행의 `tagged_at`·`tagger_version`·`taxonomy_version`(언제, 어떤 분류기·종목표로 분류했는지 — `tagging_worker_id`는 `processing` 동안만 있고 분류 결과를 쓸 때 비워지며, 모델 이름도 저장하지 않는다. 어느 실행이 분류했는지는 반복 실행 스크립트 출력과 LangSmith 기록으로만 안다), 검토 처리 결과 자체(상태 값), 서버 메모리의 되돌리기 스냅샷(재시작하면 사라짐), `tag requeue --apply`의 백업 CSV(`backups/requeue/`, 되돌린 행의 이전 값), 웹 서버 로그(예기치 못한 오류의 추적, 기능 사용 불가 경고 한 줄), 주가 갱신 실행 기록(`price_update_runs`: 시작·끝 시각, 상태, 성공·실패 수, 메시지), 수급 갱신 실행 기록(`investor_flow_runs`: 같은 칸에 순위를 매긴 날 수)과 순위를 매긴 날 목록(`investor_flow_days`: 날, 매긴 시각, 종목 수, 실행 번호), 유사도 계산 빌드 기록(`peer_builds`: 상태, 대상·성공·실패 수, 동의어표 지문, 종목표 버전, 시각, 메시지)과 프로필 행의 모델 이름·토큰 수·근거율.
- 운영 DB에 직접 데이터를 고치는 일(마이그레이션 포함)은 바뀔 행을 먼저 백업 파일로 남기고, 한 트랜잭션 안에서 바뀐 행 수를 확인한 뒤에만 커밋한다.
